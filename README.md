# ДЗ 2 -- ChannelTokenFormer

Сорочан Дмитрий, ПАДИИ3.

Python 3.10+, CPU / CUDA / Apple MPS. Из корня проекта:

```bash
python -m pip install -r requirements.txt
python -m jupyterlab
```

Запустить целиком, по порядку, каждый в чистом kernel:

1. `notebooks/00_Data.ipynb` -- UCI HAR, разные частоты, блочные пропуски.
2. `notebooks/01_EDA.ipynb` -- частоты, маски, статистики и связи каналов.
3. `notebooks/02_EdgeMTSC_pairwise.ipynb` -- четыре независимых обучения с заполнением.
4. `notebooks/03_ChannelTokenFormer.ipynb` -- adapter, три контроля/абляции, итоговый отчет.

Рабочая директория kernel -- корень проекта или `notebooks/`.
Первый запуск требует интернет для скачивания UCI HAR.
Полный протокол: 8 конфигураций, у каждой 3 CV fit и 1 финальный fit.
Продолжительность зависит от устройства; каждая эпоха печатает прогресс.
После обучения checkpoint и статистики лежат в `results/`, графики -- в `figures/`.

Последняя ячейка 03 автоматически заполняет [REPORT.md](REPORT.md) реальными метриками и выводами.
Главный вывод текущего запуска: median-imputation достаточна при умеренных пропусках, а CTF-inspired обработка дает преимущество при тяжелом 50% outage; это результат данного корпуса, не универсальное ранжирование методов.
До полного запуска отчет содержит методологию, но не выдуманные результаты.
Перед отправкой сохранить выполненные ноутбуки; проверить, что блок результатов отчета заполнен.
Данные и checkpoints не входят в git по умолчанию, таблицы и графики входят.
Повторный запуск обучения перезаписывает результаты соответствующей конфигурации.
Если менялись данные или настройки, заново выполнить оба обучающих ноутбука для согласованного сравнения.
